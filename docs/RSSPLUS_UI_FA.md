# RSSPlus Native Dashboard — راهنمای رابط تلگرام

## معماری رابط

این نسخه از **رابط بومی تلگرام** (پیام + دکمه‌های درون‌خطی و پاسخ هدایت‌شده) استفاده می‌کند. بنابراین دامنه، HTTPS و وب‌اپ جداگانه لازم ندارد. این نسخه **Mini App نیست** و نباید با یک داشبورد وب تمام‌صفحه اشتباه گرفته شود.

منابع دادهٔ رابط:
- شمارنده‌ها، اشتراک‌ها و وضعیت فعال/غیرفعال: جدول‌های اصلی Feed، Sub و User در هستهٔ RSS-to-Telegram-Bot
- عملیات فعال‌سازی و توقف: تابع اصلی activate_or_deactivate_sub
- حذف خوراک: تابع اصلی unsubs
- تغییر رسانه و شیوهٔ ارسال: تابع اصلی set_exhaustive_option
- افزودن خوراک: تابع اصلی subs
- وضعیت فیلتر، تکراری‌یاب، تأیید دستی و وب‌هوک: فایل config/rssplus.json (در زمان نمایش مجدداً خوانده می‌شود)
- فرمان‌های واقعی هسته: رجیستری COMMANDS و MANAGER_COMMANDS
- صف بررسی: پایگاه‌دادهٔ RSSPlus و کارت‌های بومی تأیید/رد

**محدودیت:** تشخیص خودکار صددرصدی تمام قابلیت‌های فعلی و آیندهٔ کد بدون رجیستری/آداپتور رسمی ممکن نیست. بخش «قابلیت‌ها» وضعیت واقعی اتصال‌های تعریف‌شده و فهرست فرمان‌های هسته را پویا نشان می‌دهد.

## شروع

در گفت‌وگوی **خصوصی** ربات، با حساب مدیر (MANAGER) دستور /panel را بفرستید. برای مدیر، /start نیز داشبورد را باز می‌کند؛ مسیر /start و انتخاب زبان برای سایر کاربران از پروژهٔ اصلی حفظ شده است.

داشبورد شامل:
- 📚 منابع: فهرست صفحه‌بندی‌شده، وضعیت لحظه‌ای، فعال/متوقف، تغییر شیوهٔ ارسال/رسانه، حذف با تأیید دوم
- 📢 کانال‌ها: کانال‌هایی که اشتراک دارند و عنوان کانال در صورت دسترسی API تلگرام، همراه با جزئیات
- 🧩 قواعد: حالت خودکار/تأیید، تکراری‌یاب و ویرایش واژه‌های شامل/حذف با پاسخ هدایت‌شده
- 🗂 صف: خبرهای منتظر تأیید و دریافت کارت تأیید/رد
- ⚙️ قابلیت‌ها: اتصال‌های فعال و فهرست فرمان‌های واقعی هسته
- ❔ راهنما: مسیر استفاده از رابط و فرمان‌های سازگار با نسخهٔ اصلی

برای افزودن خوراک جدید به کانال، ابتدا مقصد را در «کانال‌ها» انتخاب و سپس «افزودن خوراک» را لمس کنید. نشانی RSS را در پاسخ به پیام ربات ارسال کنید. افزودن اولین اشتراک به کانال جدید با دستور /sub پروژهٔ اصلی انجام می‌شود.

برای تعیین واژه‌ها، آن‌ها را با کاما یا در خط‌های جدا بفرستید؛ برای پاک کردن فهرست «پاک» بنویسید. پاسخ‌های هدایت‌شده بعد از ۱۰ دقیقه منقضی می‌شوند و پس از راه‌اندازی مجدد سرور باید از ابتدا شروع شوند.

## امنیت و UX

- رابط و رویدادهای آن صرفاً برای شناسهٔ تلگرام MANAGER و تنها در چت خصوصی کار می‌کنند.
- طول دادهٔ هر دکمه حداکثر ۶۴ بایت است و برای عملیات تخریبی تأیید دوم وجود دارد.
- خطاهای فنی به‌صورت کامل در لاگ ثبت و پیام کوتاهی به مدیر نمایش داده می‌شود.
- برای جلوگیری از شلوغی، صفحات قبلی ویرایش می‌شوند؛ اگر ممکن نباشد پیام تازه فرستاده می‌شود.
- فایل قواعد با نوشتن اتمی و مجوز 0600 ذخیره می‌شود؛ نشست و توکن وارد گیت نمی‌شوند.
- پنل روی ذخیره‌سازی ثانویهٔ اشتراک‌ها تکیه ندارد؛ وضعیت را از مدل‌های هسته می‌خواند.
- این رابط نمی‌تواند دسترسی رسانه‌ای خارج از خوراک RSS، موفقیت ارسال به تلگرام یا انتشار در شبکه‌های اجتماعی دیگر را تضمین کند.

## نصب VPS

برای Ubuntu/Debian با Git، Python 3، Docker Engine و Compose Plugin نصب‌شده:

~~~bash
git clone https://github.com/rezamahrm100-ops/RSS-to-Telegram-Bot.git
cd RSS-to-Telegram-Bot
bash rssplus-install.sh
~~~

در فایل .env می‌توان زبان داشبورد را تنظیم کرد:

~~~dotenv
RSSPLUS_UI_LANG=fa
~~~

برای نمایش انگلیسی به‌جای آن از en استفاده کنید و سپس سرویس را بازنشانی کنید:

~~~bash
docker compose up -d --build
docker compose logs --tail=100 -f
~~~

در BotFather می‌توان توضیح ربات، تصویر پروفایل، پیام About و سایر تنظیمات ارائه را برای برندسازی کامل مشخص کرد. این تغییرات از API معمول نصب روی VPS قابل تضمین نیستند.

## کنترل کیفیت

آزمون‌های Python برای اعتبارسنجی طول callback، صفحه‌بندی، ایمن‌سازی HTML، قواعد واژه‌ها، ترتیب رجیستر شدن handlerها و اتصال به هسته وجود دارد. CI ساخت تصویر Docker و تست‌های هسته را هم اجرا می‌کند. آزمون نهایی تعامل با یک کانال آزمایشی و اعتبارسنجی ارسال واقعی رسانه بعد از نصب VPS ضروری است.
