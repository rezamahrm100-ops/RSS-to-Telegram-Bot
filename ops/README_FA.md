# خبرچین: پشتیبان‌گیری محلی RSStT / RSSPlus

این ابزار صرفاً یک قابلیت عملیاتی آماده است؛ اضافه‌شدن فایل به GitHub به معنی اجرای آن روی VPS نیست.

## هدف

از **تمام پایگاه‌های SQLite تشخیص‌داده‌شده در Volume پایدار `/app/config`** به روش SQLite Online Backup نسخه گرفته می‌شود. فایل‌های غیردیتابیسی Volume و فایل‌های استقرار Docker Compose قابل‌شناسایی نیز به‌صورت محلی کپی می‌شوند. خروجی فقط در دیسک خود میزبان Docker ذخیره می‌شود و هیچ فایل یا توکنی به GitHub ارسال نمی‌شود.

## سیاست قطعی نگهداری پشتیبان — فقط روی VPS

**تصمیم مالک (۲۱ نوامبر ۲۰۲۶):** فایل‌های پشتیبان خبرچین باید فقط روی دیسک محلی همان VPS نگهداری شوند. پشتیبان بیرونی، فضای ابری، مخزن GitHub، GitHub Actions Artifact، سرور دوم، S3، rclone، rsync به میزبان دیگر و انتقال خودکار یا دستی به مقصد خارجی در محدوده این پروژه نیستند و نباید برای این مرحله پیکربندی شوند.

- مسیر پیش‌فرض پیشنهادی روی VPS: `/var/backups/khabarchin/rsstt`؛ این مسیر باید روی دیسک محلی خود VPS باشد، نه یک Mount شبکه‌ای/ابری.
- ابزار صرفاً فایل‌ها را در مسیر `--backup-root` روی **همان میزبان اجراکننده** می‌نویسد. خود ابزار هیچ قابلیتی برای آپلود یا انتقال پشتیبان ندارد.
- راه‌اندازی نسخه‌برداری زمان‌بندی‌شده یا سیاست حذف نسخه‌های قدیمی در این تغییر انجام نشده؛ ابتدا باید صحت پشتیبان و حجم آزاد دیسک VPS در محیط واقعی تأیید شود.
- نگهداری روی همان VPS در برابر حذف تصادفی یا خرابی یک فایل مفید است، اما در برابر خرابی کامل دیسک یا نابودی VPS محافظت نمی‌کند. این ریسک آگاهانه پذیرفته می‌شود؛ **نباید با راه‌اندازی پشتیبان خارجی بدون درخواست جدید مالک حل شود**.
- روی GitHub فقط سورس اسکریپت، آزمون ساختگی و مستندات می‌مانند؛ هیچ فایل دیتابیس، `.env`، توکن یا آرشیو تولیدی به آن ارسال نمی‌شود.

## استفاده در میزبان Docker مورد اعتماد

پیش‌نیازها: Python 3.9+، Docker CLI، دسترسی خواندن به Volume و فایل‌های Compose و فضای دیسک کافی.

```bash
python3 ops/rsstt_backup.py audit --container rssplus

python3 ops/rsstt_backup.py backup --container rssplus \
  --expect-databases 2 --backup-root /var/backups/khabarchin/rsstt

python3 ops/rsstt_backup.py verify /var/backups/khabarchin/rsstt/rsstt-YYYYMMDDTHHMMSSZ-XXXXXXXX
```

ممکن است برای خواندن فایل‌ها به اجرای فرمان با حساب مجاز یا `sudo` نیاز باشد. این ابزار کانتینر را متوقف، ری‌استارت یا جایگزین نمی‌کند؛ به تلگرام پیام نمی‌فرستد و هیچ بازیابی روی پایگاه اصلی انجام نمی‌دهد.

هر Snapshot پایگاه داده با `sqlite3.Connection.backup` و `PRAGMA integrity_check` آزموده می‌شود. سپس یک کپی جداگانه از Snapshot نیز باز می‌شود تا امکان بازیابی مستقل کنترل شود. فایل‌های جانبی `-wal`، `-shm` و `-journal` خام کپی نمی‌شوند. پوشه خروجی مجوز `0700` و فایل‌ها مجوز `0600` دارند.

## اعتبارسنجی محل نگهداری و دیتابیس

برای اجرای VPS، ابزار پیش از نوشتن پشتیبان، نوع فایل‌سیستم مسیر مقصد را از `/proc/self/mountinfo` بررسی و فایل‌سیستم‌های شبکه‌ای یا موقت شناخته‌شده (مانند NFS، SMB، SSHFS، rclone، tmpfs) را رد می‌کند. این کنترل جانشین ممیزی استقرار نیست و همه حالت‌های غیرمعمول ذخیره‌سازی مجازی را تشخیص نمی‌دهد.

طبق سورس RSStT، فایل‌های `.env` می‌توانند مقدار `DATABASE_URL` را بازنویسی کنند؛ ابزار اکنون متغیرهای دیتابیس در محیط کانتینر و فایل‌های `.env` قابل‌شناسایی را کنترل می‌کند و فقط مسیر صریح SQLite داخل Volume را می‌پذیرد. در صورت پایگاه خارجی، نشانی مبهم یا فایل مفقود عملیات متوقف می‌شود. **نسخه واقعی VPS هنوز گرفته نشده است.**

## موارد توقف ایمن

در صورت کانتینر مبهم، نبود Volume در `/app/config`، استفاده از PostgreSQL، نشانی دیتابیس خارجی/مبهم، وجود Symlink در داده‌ها، تعداد نامنتظره پایگاه‌ها یا فقدان فایل استقرار Compose، عملیات متوقف می‌شود. این موارد باید قبل از ادعای پشتیبان کامل بررسی شوند.

یک Snapshot سالم **معادل آزمون عملی راه‌اندازی مجدد ربات، حفظ اشتراک‌ها و انتشار در تلگرام نیست**. تنظیمات و داده‌هایی که خارج از Volume و فایل‌های Compose کشف‌شده باشند نیز ممکن است پوشش داده نشوند.

**هشدار امنیتی:** نسخه‌های پشتیبان احتمالاً حاوی `.env`، توکن ربات، تنظیمات محرمانه و داده‌های کاربران هستند. آن‌ها را هرگز به مخزن GitHub، Issue، Pull Request، Artifact یا Log ارسال نکنید. حذف دوره‌ای و بازیابی در محیط زنده در این تغییر اضافه نشده‌اند. **پشتیبان خارجی طبق تصمیم مالک ممنوع است مگر با درخواست جدید و صریح.**

## آزمون ساختگی در مخزن

```bash
python3 -m unittest discover -s tests -p 'test_khabarchin_backup.py' -v
```

دوازده آزمون تعریف شده‌اند: دو SQLite ساختگی، WAL، تشخیص دستکاری فایل، مغایرت تعداد پایگاه‌ها، مسیر ناامن و پیوندهای نمادین در داده‌ها، ریشه مقصد و پوشه‌های والد. اجرای این آزمون‌ها روی SHA فعلی در GitHub Actions هنوز تأیید نشده است. گردش‌کار GitHub Actions فقط داده ساختگی می‌سازد و هیچ اتصال به VPS ندارد.
